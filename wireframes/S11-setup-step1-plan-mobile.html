RReview and save
  1. One full-screen step at a time. No side step list fits at 390px, so a compact progress header replaces it: current step, its name, and a 4px progress bar. This is a designed mobile layout, not the desktop step list reflowed - see the note inside the frame for why a phone still has to reach this wizard. FR9.1
  2. Tappable step drawer. Tapping the header opens the sheet shown in the second device: every step, its number and whether it is done, so a step can be revisited without walking forward and back one screen at a time. Steps are non-linear once visited, per design.md. FR9.1
  3. Upload replaces, never appends. One plan image per site. The filename, its pixel dimensions and who uploaded it stay visible after upload, because an administrator returning to this step later must be able to confirm which file is live. FR9.1
  4. Ground extent in metres. 300 x 200 m for Riverside Arena. This is what turns the cell grid in step 2 into a real area instead of an arbitrary count. FR9.1
  5. Scale by drawing a known distance, not by typing a guess. The 50 m line across the south stand is a real, checkable distance on the plan, so the scale the whole grid depends on is anchored to something a person on site can verify with a tape measure. FR9.1
  6. Continue is the only enabled primary action; Back is disabled. There is no step 0, so Back is present but inert here for consistency with every later step's action bar, rather than the bar changing shape between steps. Enter submits, Esc cancels the wizard and raises D10 if any field above is dirty.
  7. The drawer names every step and its state. A filled marker is done, an outlined one is not yet visited; this is the only place progress across all eight steps is visible on a phone. FR9.1
  8. Closing the drawer returns to exactly where setup was. The drawer is a sheet over the current step, not a navigation away from it, so opening it to check progress never loses in-progress field values.
