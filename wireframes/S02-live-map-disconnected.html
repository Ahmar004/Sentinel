  1. The banner names the failure, not a euphemism. "Connection lost", not "updating" or a spinner with no words, because a coordinator under time pressure must know in one glance that nothing on screen is being refreshed. NFR6 SRS 3.4
  2. The connection chip carries no invented number. Latency has no meaning without a server to measure it against, so it reads "n/a" rather than the last measured value, which would misrepresent a dead link as a slow one. NFR6
  3. Every zone tile reads a dash over 100% gap. Not one risk band remains anywhere on this screen. A zone tile that kept showing 0.31 NORMAL after the feed died would be the exact failure this frame exists to rule out: an unknown state rendered as a safe one. FR3.4 FR6.3 SRS 2.3
  4. The whole 2400-cell grid is gap. The client keeps its own clock and ages every cell forward every second regardless of whether new data arrives, so ten seconds of silence is ten seconds of cells crossing the gap horizon on their own, with no server needed to tell it to do so. FR6.3 SRS 2.7
  5. A handful of cells are still mid-age. These were mid-flight through the stale window at the instant the socket dropped, so they have not yet crossed the 10 s gap horizon. In a few more seconds every one of them joins the rest as gap too - this frame is a snapshot of a state that is still actively decaying, not a new steady state. FR3.4 SRS 2.7
  6. The disabled buttons state why, not just that. Acknowledge and Suggestions both require a round trip to a server that is not there, so each carries its own reason rather than going quietly grey with no explanation. NFR6
  7. Same argument, desktop scale. The banner and the connection chip repeat the failure in the same words as mobile, because the two layouts must never disagree about whether the system is live. NFR6
  8. Zone strip states the count that is missing, not just a dash. "0 obs / 0 dwell / 0 stale / 2400 gap" for zone A makes the honesty invariant auditable rather than merely asserted: every one of the zone's cells is accounted for as unknown. FR4.6 SRS 2.3
  9. Drone footprints and the alert pin are withheld, not frozen in place. Telemetry comes over the same dead socket as everything else, so drawing a footprint where a drone was ten seconds ago would assert a position Sentinel no longer knows. The map says less rather than saying something false. FR6.3 SRS 2.5
  10. The legend and layer toggles keep working. They describe the visual language, not a live measurement, so they are unaffected by the drop - only what they are legending against has gone to gap. NFR5
  11. The alert card is explicitly labelled frozen. It keeps its last known band in words rather than its coloured outline, and states in the card itself that the current state is unknown - the honesty invariant applied to an alert, not only to a cell. FR5.1 SRS 2.3
  12. Zone boundaries remain drawn. They are an administrator-configured layout, not a live measurement, so keeping them on screen during a drop does not claim anything about the current crowd. FR6.2
