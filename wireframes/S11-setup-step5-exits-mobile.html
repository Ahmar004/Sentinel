Capacity here is the denominator for exit occupancy on the live map - it is not a planning tool. Sentinel does not design, size or schedule exits; it measures what passes through the ones that already exist.

  1. Capacity is a denominator, stated as one up front. The honest note sits above both exits because this is the boundary an examiner will test first: Sentinel never plans, sizes or schedules an exit, it only measures throughput against a number the administrator supplies. FR9.5
  2. Each exit groups a set of exit-attributed cells under one name. E1 South Gate holds 8 cells, E2 North Gate holds 6, matching the attribute counts painted in Step 4 - an exit cannot claim a cell that was not marked exit there. FR9.5
  3. The map thumbnail shows which cells the name refers to, so "South Gate" is never just a label floating apart from the grid - tapping it opens cell selection to add or remove cells from the group. FR9.5
  4. Capacity is a plain number in people per minute, editable inline, matching srs.md's unit for exit occupancy exactly - no derived units, no rate conversions the administrator would have to trust blindly. FR9.5
  5. An exit under edit is visually distinct - a stronger border and focus ring on E2 - so a long list of exits never leaves it ambiguous which one the open keyboard is about to change.
  6. Add exit has no upper bound stated, unlike zones in Step 6 - srs.md fixes the zone count at two to four but places no limit on exits, so the control stays enabled regardless of how many already exist. FR9.5
