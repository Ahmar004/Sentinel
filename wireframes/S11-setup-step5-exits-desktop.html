  1. Exits group exit cells; they do not create new ones. The 14 exit cells painted in Step 4 are exactly the cells available to group here - 8 into E1, 6 into E2 - so a screen for naming exits can never invent an exit cell the attribute pass did not mark. FR9.5
  2. Capacity is entered once per named exit, in people per minute - E1 South Gate at 1200, E2 North Gate at 900, matching the canonical dataset - because exit occupancy needs one denominator per exit, not per cell. FR9.5
  3. "Group ungrouped exit cells" is disabled and says why. With 14 of 14 exit cells already assigned, there is nothing left to group; the control reappears active the moment Step 4 is revisited and a new exit cell is painted. FR9.5
  4. The honesty boundary is stated in words on the same screen. Capacity feeds one risk feature, exit occupancy - Sentinel never uses it to plan, size or redesign an exit, which is the scope boundary CLAUDE.md and srs.md both hold.
  5. No "current" occupancy column appears on this screen. Occupancy is a live measurement produced once drones are observing; showing a number for it during setup, before any observation exists, would be exactly the invented value the honesty invariant forbids.
