A usability guard only - the setup wizard holds enough hand work that losing it silently would go unnoticed until much later.
  1. The dialog names the exact step or tab and the exact thing that would be lost. "2 cells reassigned" and "14 cells painted" are concrete counts, not a generic "you have unsaved changes" that leaves the administrator guessing what is at stake.
  2. Three actions, always in the same order: discard and leave, save and leave, stay - with Stay visually last but marked as the default via type="submit" and autofocus, so Enter and a plain click on the emphasised button do the same safe thing.
  3. Stay is the default and Esc chooses it. Leaving is never the path of least resistance; staying on a half-finished configuration screen is.
  4. Discard is a real choice, not a trap. It is type="button" with its own explicit label naming the destructive action in full, never "No" or "Cancel", which would be ambiguous about which direction is destructive.
  5. Save and leave exists because losing setup work is worse than an extra click. An administrator who meant to save can do so from the same dialog instead of returning to the tab first.
  6. This maps to no requirement. It is a usability guard, stated here because the setup wizard holds enough work that a silent loss is exactly the kind of defect an examiner finds by accident rather than by reading a requirement.
