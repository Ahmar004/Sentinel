  1. Current and new value sit side by side, never one replacing the other. An administrator reads 0.70 and 0.65 at once instead of having to remember the old value after typing the new one. FR9.7
  2. The new value is a real input, not a slider alone - an administrator can type an exact number, which matters when the number is what an examiner will ask about. FR9.7
  3. The number line shows the shrinking band directly. The zone between 0.65 and 0.70, shaded and outlined in the watch and normal colours, is exactly the range that changes classification if this save goes through. FR9.7
  4. 23 cells is stated as a count, not implied by the shading alone. This is the requirement itself: an administrator sees what lowering a threshold will do before saving, in a number that can be checked against the map. FR9.7
  5. Save and Cancel are a real form. Save is type="submit", Cancel is type="button"; Enter submits, Esc cancels, and focus is trapped on the dialog while open and returned to the triggering Edit button on close.
  6. Density threshold is shown but disabled. This dialog is editing the risk threshold; the density threshold stays visible for context because the two are read together everywhere else in the product, but changing it is a separate action. FR9.7
  7. The audit consequence is stated in the dialog itself, not only in a toast afterwards. An administrator commits to "this becomes an audit entry with 0.70 and 0.65" before clicking Save, not after. FR9.9
