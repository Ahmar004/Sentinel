Only Zone B's configuration entry matches the active Zone filter. Zone A and Zone C were configured in the same setup pass, and reappear here the moment the zone filter is cleared - filters narrow the same underlying log, they never create a separate one per tab.
  1. Eight filter fields, each narrowing independently. Time range, zone, cell, risk band, alert status, suggestion status, actor and free text sit in one bar; picking any one narrows the result set without resetting the others. FR8.3
  2. Active filters are chips, each individually removable. Zone and time range are both applied here; removing one re-widens the set without touching the other, and Clear all resets both at once. FR8.3 C09
  3. The narrowed count is stated, not just the rows. "7 results narrowed by 2 filters" tells the coordinator filters are doing something, distinct from there being only 7 events in the whole 30 day retention. FR8.3
  4. The resolution notice names the actual rate, 0.1 Hz, because the range exceeds the full-rate hour. The 24 hour range spans yesterday's incident, so cell samples in that part of the range come back at one per 10 s and the screen says so instead of implying 1 Hz precision it cannot deliver. FR8.2
  5. Four tabs scope the same underlying stream. All, Alerts, Suggestions and Configuration changes are views over one filtered set, not four separate queries - the Configuration tab's own note demonstrates this by naming what the zone filter is hiding. FR8.1
  6. Every row carries type, time, zone, cell and a one-line summary, exactly as design.md specifies, so a row is legible without opening it. FR8.1
  7. Suggestion rows carry the outcome verdict as its own chip, separate from status. SG-0771 shows CONFIRMED and IMPROVED -0.17 side by side; A-1042's still-open suggestions show PROPOSED with "window not started" rather than a guessed verdict. FR8.6
  8. Every row names its actor, not only its time. System-raised events read "system", human actions read the username and what they did - acknowledge, confirm, or save - because NFR4 requires who acted, not only when. NFR4
  9. Row actions open S09 for detail or S10 for the surrounding period, so a coordinator moves from "what happened" to "watch it happen" without leaving the filtered list behind. FR5.6
  10. The header states the retention window plainly. "30 day audit retention" sits in the top bar on every visit to this screen, so a coordinator never has to guess how far back a search can reach. FR8.2 NFR4
