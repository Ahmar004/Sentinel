  1. The account is named, not implied by which row was clicked. "Deactivate k.javed?" in the header and again in the body, so a screen reader user or a fast scroller cannot confirm the wrong account. FR10.5
  2. Two consequences are stated separately: sign-in stops, audit history does not. Splitting them is the point - a reader who only heard "can no longer authenticate" could reasonably assume the account's record disappears too, and it does not. FR10.5
  3. Reversibility is stated in the dialog's own words, not left to be inferred from an Accounts screen the administrator has not opened yet. This is what keeps the action reading as deactivate rather than delete. FR10.5
  4. Cancel carries the initial focus, not Deactivate. The destructive action is never the keyboard default, so pressing Enter out of habit lands on Cancel. FR10.5
  5. Confirm is type="submit" on a real <form onsubmit>; Cancel is type="button". Enter submits, Esc cancels, focus is trapped in the dialog while open and returns to the account row's action button on close.
  6. Submitting disables both buttons and shows progress in words, not just a spinner. "Deactivating..." on the button itself states what is happening, so a slow response does not read as a frozen dialog.
  7. A failed request leaves the account visibly untouched and offers Try again in place. Per SRS 3.4, a failed request never leaves a previously fetched value looking live; here the account's ACTIVE status is restated so nothing is ambiguous about what did or did not happen.
  8. Deactivating the account you are signed in as is refused before any request is sent, with the reason given in plain words, because the account performing the action must remain able to see the result of it. There is no Deactivate button to mis-tap in this state at all. FR10.5
  9. Mobile keeps the same two consequences and the same reversibility sentence, as a full-width sheet rather than a centred modal, with the same focus order.
  10. The Accounts table behind the scrim is simplified but carries the real five accounts from the canonical dataset, so the dialog is seen in the context it actually opens from rather than floating over an empty page. `S13` itself is drawn in a later batch. FR10.2
