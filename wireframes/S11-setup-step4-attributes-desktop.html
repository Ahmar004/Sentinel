  1. The brush is one control with four states, never four separate tools. Walkable, Exit, Barrier and Obstruction are the only static cell attributes the SRS glossary defines, so the palette offers exactly these four and nothing invented. FR9.4
  2. Running counts match the canonical dataset exactly - walkable 2104, exit 14, barrier 118, obstruction 164, summing to the full 2400-cell grid - so a reviewer can check this screen's arithmetic against srs.md without opening a second document. FR9.4
  3. Manual annotation is stated as the guaranteed path, in words, above the fold. This is the acceptance test for FR9.4 made explicit: with the proposal list empty an administrator can still mark every cell by hand and save a complete configuration. FR9.4
  4. The one proposal left unreviewed in Step 3 surfaces here, not on a page of its own. Design.md is explicit that Proposals has no tab on the Site configuration screen later, so this is also the pattern that screen's Attributes tab reuses. FR9.3
  5. The painted grid shows a crop, not all 2400 cells. A legible crop near North Gate proves the mechanism; the running counts on the left, not the crop, are the source of truth for the whole site. FR9.4
  6. Attribute colours are grey shades and patterns scoped to this screen (attr-walkable, attr-exit, attr-barrier, attr-obstruction), never the obs-* or band-* classes that render live observation and risk, so a setup screen can never be misread as a live one.
